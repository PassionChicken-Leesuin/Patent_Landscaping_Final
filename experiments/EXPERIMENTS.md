# Agentic 시스템 실험 로그

> **범위:** 2026년 7월 질의 기반 직접판정 시스템의 실험 기록이다. 6월 논문의
> Snorkel/MAS+SciBERT 수치는 비교 기준으로만 인용하며, 아래 Agentic 실험과는
> 학습·판정 경로가 다르다. 통합 작업 폴더의 전체 구분은 `../PROJECT_MAP.md`,
> 7월 시스템 설명은 `../README_MAS.md`를 참고한다.

목표: 자연어 질의 → 자료수집 → 문장형 기준서(validator+HITL 루프) → 기준 엄밀 판정(validator 루프) 시스템을
6개 골드 도메인에서 기존 Snorkel/MAS+SciBERT 대비 최고 성능으로 끌어올리기.

기존 베이스라인 (논문, SciBERT 다운스트림, 6개 도메인 평균):
- Snorkel: AUC 0.881 / Macro-F1 0.730 / Recall 0.551 / Precision 0.718 / Acc 0.821
- MAS(구): AUC 0.945 / Macro-F1 0.833 / Recall 0.781 / Precision 0.783 / Acc 0.883

주의: 위 베이스라인은 "의사라벨→SciBERT 학습" 경로, 아래 실험은 "에이전트 직접 판정" 경로 —

### 통제 재현성 기준선 + 기준서 루프 수렴 (2026-07-22, repro1)
P6/P7 장치를 실전 검증. 기준서 루프가 8→7→6→6→7로 비수렴하던 문제(repro-live-a 1차)는
세 겹의 원인이었고 각각 코드로 해소:
- **결정론 이슈의 앵무새 재보고**: 비평자가 원장의 open 코드를 문서와 대조 없이 반복
  (C6/C7이 A6/A7을 커버해도 AXIS_COVERAGE 재보고) → `reconcile_issues`가 결정론
  네임스페이스 코드를 코드 검사 결과로만 판정.
- **비결정론 이슈의 앵커링**: MOF 커버 기준(C6)이 존재해도 COVERAGE:MOFS 재보고 →
  2라운드 지속 critical은 원장 없는 새 컨텍스트의 **blind 검증자**가 문서만 보고
  해소 여부 판정(`verify_issue_resolution`), 해소면 원장 닫음. 실측: 두 실행 모두
  blind 검증이 앵커링 이슈 2건씩 닫고 그 다음 라운드 critical 0으로 승인.
- **중복 패치**: 해소 안 된 걸로 오인된 이슈에 동일 기준을 재추가(C8/C9 중복) →
  `apply_patches` add에 정규화 문장 dedup.
`--strict` 임계값은 회귀 게이트 목적에 맞게 측정 기준선 직하로 보정(stance≥0.85,
κ≥0.70, pos-자카드≥0.65, Spearman≥0.80). 축 이름·질문 문구 자카드는 LLM 명명 분산을
재는 것이라 게이트에서 제외하고 정보성으로만 보고(축 0.182, 질문 0.0 — 판정 재현성과
별개로 낮음. 축 어휘 통제는 후속 과제).

### 범위질문 로직 강화 (사용자 제안: "헷갈리는 경계를 정하는 로직을 명확히")
초기 open_questions는 "LLM이 알아서" 자유생성이라 재현성·정확성이 약했음(hydro에서 진짜 병목보다 좁은
질문을 냄). 3단계로 로지컬화:
- **1번 판정 diff 측정** (`boundary_probe.py`): 후보 경계마다 broad_rule/narrow_rule을 명시하고, 풀 표본
  60건을 두 규칙으로 실제 판정 → **라벨이 갈리는 특허 수(flip)** 를 세어 필터·랭킹. hydro 실측: Q1 회수경계
  60건 중 41건(68%), Q2 분리경계 30건(50%) 갈림. why_it_matters가 짐작→실측치로 교체됨. KeyPool 병렬 재사용.
- **2번 후보 소스 명시 연결**: corpus의 suspected_boundary_cases + mismatch를 "CANDIDATE SCOPE BOUNDARIES"
  블록으로 강조 전달 → 후보 recall↑(probe가 정밀도 보장하므로 넉넉히 뽑아도 안전).
- **3번 닫힌 루프** (`judge.boundary_feedback_round`, `--boundary-loop`): 판정에서 boundary/abstain/경계점수로
  몰린 특허를 모아 공통 범위 모호성을 새 질문으로 도출 → probe 검증 → HITL → 해당 특허 재판정.
- 부수 수정: (a) 배치 HITL resume 시 기준서를 재작성하던 버그 → pending 초안 저장/복원(질문 ID 고정),
  (b) gpt-4o 기준서가 completion 길이한도 초과 시 크래시 → scope_decisions 15개 상한 + LengthError 재시도.

### 능동적 범위질문 (open_questions) — 기능 추가
기준 작성 에이전트가 초안과 함께 "판정을 좌우하지만 증거만으로 못 정하는 범위 경계"를 스스로 1~4개
표시(`CriteriaDocOut.open_questions`) → 파이프라인이 validator 루프 **전에** 사람에게 먼저 질문(HITL) →
답을 authoritative하게 기준서에 반영. 무인 모드는 tentative_default로 자동 진행+기록. hydro 검증: 시스템이
"수소 회수/생산/공급계를 포함할지"를 스스로 물었고, "포함" 답변이 recall +0.10(정밀도 유지)을 냄.

### 종합 통찰 (파일럿 라운드)
- **기준서 생성의 run-to-run 분산(±0.05~0.08 F1)이 요소 효과를 압도** → 예산소진 시 critical 최소 버전 선택으로 개선(코드 반영).
- 최적 관측 구성 = **E3** (CONFLICT RULE + purpose 판정 + scope_decisions + 위키 리서치). 전체 평가는 이 구성으로.
- hydro 잔여 recall 격차는 도메인 범위 환유성(저장⊃생산·연료전지?) — 시스템이 질문을 생성하도록 되어 있고, 무인 모드에선 자동응답 기록됨. **사용자 답변 필요** (PENDING_QUESTIONS.md).

### E2 진단
- 판정 로직 결함: 제외기준이 "look-alike 식별용"인데 판정자가 **veto**로 오용 → C 충족 + E 인용 시 무조건 out. (예: family 45934325 — C1,C2,C3 matched인데 score 0.1)
- 기준서 validator 비수렴: MOF 미언급 같은 minor 이슈로 계속 revise → 예산 소진.
- 조치(E3): ① 판정 프롬프트에 CONFLICT RULE(제외는 veto가 아님) + 용도(purpose) 식별 지시, ② C∩E 충돌 시 2차 확인 강제(코드 가드), ③ critique에 severity 도입 — critical 없으면 approve 처리, ④ 판정감사 재감사 중복 제거.

### E1 진단
- 버그: Wikimedia가 기본 UA를 403 차단 → 증거노트 0개 → 기준서가 corpus+내부지식만으로 좁게 작성됨.
- 구조 문제: 범위(생산/정제/연료전지 포함 여부)가 **암묵적 좁은 기본값**으로 결정됨. HITL off의 자동답변도 "보수적으로"라서 좁힘을 강화.
- 조치(E2): ① UA 수정+에러 로깅, ② CriteriaDoc에 scope_decisions(클러스터별 in/out 명시 판결) 추가 + validator가 "주요 풀 클러스터를 근거 없이 out 처리"를 결함으로 검사, ③ 자동답변 정책을 "증거·풀 구성에 최대 정합" 으로 교체.
